# gitaway

Лёгкий веб-интерфейс для git и файлов на сервере. Один бинарник на Go, запускается
от имени обычного пользователя (как терминал после входа по SSH) и открывается
в браузере с любого устройства. Альтернатива тяжёлому code-server для работы с ветками.

Ключевые отличия, ради которых проект существует:
- несколько веток одновременно: каждая ветка это вкладка со своим `git worktree`;
- fetch, pull и push всегда отдельные операции, со счётчиками ahead/behind;
- таблица файлов: последний коммит, автор, дата коммита, дата изменения на диске, статус;
- серверная панель (скрыта по умолчанию, открывается кнопкой «Открыть локальную ФС»):
  перетаскивание файлов из ветки в папку сервера с диалогом конфликтов;
- терминал в браузере.

План и приоритеты: `docs/ROADMAP.md`. Принятые решения и API: `docs/DECISIONS.md`.

## Команды

    go build ./...            # сборка
    go vet ./...
    go test ./...             # нужен git; тесты создают временные репозитории
    go test -race ./...
    gofmt -l .                # должно быть пусто
    make build                # bin/gitaway с версией из git describe
    ./bin/gitaway -config config.json   # config.example.json как образец

CI (`.github/workflows/ci.yml`) на каждый push: build, vet, test -race, gofmt.
Публичный репозиторий, стандартный раннер, бесплатно.

## Устройство

    cmd/gitaway/       точка входа, сборка зависимостей, graceful shutdown
    internal/config/   настройки (JSON, неизвестные поля запрещены, "~" раскрывается)
    internal/fsx/      Sandbox: все пути из запросов проходят через него
    internal/gitx/     обёртка над системным git (os/exec): ветки, статус, worktree,
                       операции, последний коммит по элементам каталога (+ кэш по HEAD)
    internal/auth/     Authenticator (token сейчас, PAM потом), сессии, лимит попыток
    internal/store/    repos.json и settings.json (0600, атомарная запись)
    internal/jobs/     KeyedLock: одна операция на репозиторий или каталог
    internal/copyop/   копирование между панелями: план -> решения -> атомарная запись
    internal/session/  процессы в pty (терминал, задачи, clone): буфер вывода, переподключение
    internal/tasks/    задачи: мои скрипты, .gitaway.json с доверием, автоопределение, сценарий sh
    internal/github/   deploy-ключи GitHub: разбор адреса, ключ ed25519, закреплённый ключ хоста
    internal/server/   HTTP API, middleware, обработчики
    web/               интерфейс через go:embed: index.html и ES-модули в web/app/
                       (main, actions, store, router, commands, ui, i18n/ru.js, views/)
    proto/             прототипы PAM, терминала, замера (отдельный модуль, CI не собирает)
    packaging/         systemd-юнит gitaway@.service, пример nginx
    tools/uicheck/     заглушка API и сценарий Playwright: проверка интерфейса без Go
    tools/vendor/      сборка web/vendor/ (CodeMirror, xterm.js) из закреплённых тегов GitHub
    vendor/            зависимости Go (go mod vendor): сборка без доступа к proxy.golang.org

## Правила (не нарушать без явного решения пользователя)

Безопасность:
- Любой путь из запроса только через `fsx.Sandbox` (Resolve, ResolveNew, ResolveUnder).
  Никаких `filepath.Join(base, userInput)` напрямую.
- git вызывается только через `gitx.Runner`, аргументы списком. Имена веток, remote и URL
  проверяются валидаторами из `gitx/validate.go` до вызова. Значение из запроса никогда
  не идёт в позицию, где git может принять его за опцию.
- Изменяющие запросы: сессия + `X-CSRF-Token` + проверка Origin (обёртка `s.api`).
- Копирование в `.git` и из него запрещено. Symlink не копируются.
- Ошибки наружу только через `s.fail` (единый формат `{"error":{"code","message"}}`),
  внутренние детали в лог, не клиенту. Пароли, токены и query-строки не логируются.
- Учётные данные в URL вырезаются (`stripCreds`, `redact`).

Компактность:
- Бэкенд на стандартной библиотеке. Бюджет внешних зависимостей: PAM (`msteinert/pam`,
  за тегом сборки `pam`), pty (`creack/pty`), WebSocket (`coder/websocket`). Новую
  зависимость сверх этого добавлять только с согласия пользователя.
- Фронтенд без шага сборки: обычные ES-модули, без фреймворка. Сторонние библиотеки
  (xterm.js, редактор) кладутся в `web/vendor/` с лицензией и закреплённой версией.
  CDN нельзя: CSP сервера `default-src 'self'`, и сервер может быть без интернета.
- Зависимости Go лежат в `vendor/` (сборка без сети). После изменения go.mod: `go mod vendor`.
- Не делаем: плагины, LSP, многопользовательский режим, редактор конфликтов слияния,
  API других хостингов кроме GitHub.

Стиль:
- Комментарии в коде и тексты интерфейса на русском. Сообщения коммитов на английском.
- Ошибки ввода в gitx это `*gitx.InputError` (сервер отдаёт 400).
- Тесты: табличные, `t.TempDir()`, изолированное окружение git (HOME, GIT_CONFIG_NOSYSTEM,
  автор и коммиттер в env), реальный git вместо моков. Новый обработчик = интеграционный
  тест в `internal/server` через `httptest`.
- После правок запускать `gofmt`. Если Go в окружении нет, выравнивать вручную
  и проверять результат по CI.
- Интерфейс: тексты только через `t('ключ')` из `web/app/i18n/ru.js`; действия регистрируются
  командами (`commands.register`), кнопки и меню вызывают команды или `actions.js`.
  После правок интерфейса прогонять `tools/uicheck` (при изменении API обновить заглушку).

## Окружение и процесс

- Целевой сервер пользователя: RED OS 8 (RPM, glibc 2.36, x86_64), nginx перед gitaway
  на отдельном порту с TLS, firewalld выключен. Тесты на сервере пользователь запускает сам.
- Облачная сессия Claude Code: Go может отсутствовать, установка пакетов может быть
  закрыта. Тогда проверка идёт через push и CI; читать логи CI через API GitHub.
- Пользователь общается на русском.
- Работа ведётся в `main` небольшими коммитами; каждый коммит должен проходить CI.
