# План развития (предложение, ждёт утверждения)

Цель: инструмент, которым реально пользуются каждый день, и который остаётся маленьким.
Один бинарник, понятный за вечер код, минимум зависимостей.

## Ориентиры размера (проверять при каждом релизе)

- бинарник: до 20 МБ (code-server: пакет около 229 МБ)
- память в простое: до 30 МБ
- первая загрузка интерфейса без редактора и терминала: до 300 КБ
- внешние зависимости Go: не больше трёх (pty, WebSocket, PAM)

## Найденные пробелы

1. **Нет API для серверной папки.** Правая панель из макета не может показать содержимое
   папки: `/api/tree` работает только с репозиториями. Нужны `GET /api/fs?dir=&path=`
   (список с размером, датами), `POST /api/fs/mkdir` и выбор папки по умолчанию.
2. **Нет stage, commit и diff.** Без них это просмотрщик, а не git-инструмент.
3. **Терминал из прототипа берёт xterm.js с CDN**, а CSP сервера это запретит.
   Библиотеки нужно положить в `web/vendor/` и вшить в бинарник.
4. **Длинные операции синхронные** (таймаут 60 с). Для fetch/pull/push хватит, для clone
   нет. Вместо отдельной системы задач достаточно потокового ответа (SSE) с выводом git.
5. **Интерфейс не узнаёт об изменениях извне** (правка в терминале, pull). Дешёвое решение:
   перечитывать статус при возврате на вкладку и после каждой операции, без fsnotify.
6. **Порт открыт всем**, если на сервере выключен файрвол. Нужен `allow_cidrs`
   в конфигурации: проверка адреса клиента до входа (несколько строк кода).
7. Проверка «файл изменился на диске» сравнивает секунды. Лучше наносекунды.

## Версия 0.1: полезный минимум

По порядку, каждый пункт отдельным коммитом с тестами:

1. **API серверной папки** (пробел 1) и настройки в `data_dir/settings.json`
   (папка по умолчанию, копировать или перемещать, спрашивать при перезаписи).
2. **Git: stage, unstage, commit, diff файла, отмена изменений** (с подтверждением).
3. **`allow_cidrs`** и наносекунды в проверке mtime (пробелы 6 и 7).
4. **Интерфейс по макету**: три колонки (ветки, файлы ветки, сервер), вкладки веток,
   таблица с коммитами, контекстное меню веток, диалог конфликтов, шестерёнка настроек.
   Сразу адаптивный: на телефоне одна колонка с переключением «Ветки / Файлы / Сервер /
   Терминал». Работа с телефона это то, чем code-server плох, а нам подходит по названию.
5. **Редактор** (вшитый, без сборки) и **терминал** (после проверки прототипа на сервере).
6. **PAM** (после проверки прототипа на RED OS). Режим token остаётся для разработки.

## Версия 0.2

- **Deploy-ключи, простой вариант**: сгенерировать ключ, показать публичную часть
  и прямую ссылку `github.com/<owner>/<repo>/settings/keys/new`, кнопка «Проверить».
  Это закрывает основной сценарий без регистрации GitHub App.
- Клонирование по URL с потоковым выводом (пробел 4).
- Журнал действий (clone, pull, push, копирование, замена файлов) в отдельный лог.
- Встроенный TLS (`tls_cert`, `tls_key`) для тех, у кого нет nginx.
- RPM-пакет.
- CI: сборка с тегом `pam` (libpam-dev на Ubuntu), чтобы PAM-код хотя бы компилировался.

## Позже и только если понадобится

- Device Flow GitHub с автоматическим добавлением deploy-ключа.
- Граф коммитов (до этого достаточно списка `git log`).
- TOTP как второй фактор входа.

## Сознательно не делаем

Плагины, LSP и автодополнение, многопользовательский режим, редактор конфликтов слияния,
API GitLab и Bitbucket, собственная база пользователей, встроенный VPN.
Для доступа издалека документируем SSH-туннель, nginx с TLS и WireGuard или Tailscale.
