# План развития

Цель: инструмент, которым реально пользуются каждый день, и который остаётся маленьким.
Один бинарник, понятный за вечер код, минимум зависимостей. Главный сценарий: работа
с кодом на сервере из браузера, в том числе с телефона: правка, git, сборка, тесты.

## Ориентиры размера (проверять при каждом релизе)

- бинарник: до 20 МБ (code-server: пакет около 229 МБ)
- память в простое: до 30 МБ
- первая загрузка интерфейса без редактора и терминала: до 300 КБ
  (редактор и терминал грузятся, только когда открыты)
- внешние зависимости Go: не больше трёх (pty, WebSocket, PAM)

## Версия 0.2: сборка и тесты из браузера

- **Сеансы**: один механизм для терминала, задач, clone и долгих операций git. Процесс в pty,
  кольцевой буфер вывода, переподключение после закрытия браузера, остановка, код выхода.
- **Задачи** из трёх источников, в одном выпадающем списке «▶»:
  - автоопределение: `Makefile`, `go.mod`, `package.json`, `Cargo.toml`, pytest;
  - **мои скрипты**: именованные цепочки команд (сборка, бэкап папки и т.п.), общие или
    для одного репозитория, с подстановками `{worktree}`, `{branch}`, `{date}`;
  - `.gitaway.json` в репозитории, только после подтверждения доверия.
- **Ссылки из вывода** (`file:line:col`, трассировки Python) и список «Проблемы».
- Повтор последней задачи (F5), «запускать при сохранении», уведомление о завершении.
- Окружение как при входе по SSH: задачи и терминал через `bash -l`.
- Быстрое открытие файла (`git ls-files`) и поиск по проекту (`git grep`).
- История ветки (`git log`) и diff коммита; diff рядом.
- Скачивание файла или папки zip-архивом, загрузка перетаскиванием с компьютера.
- Deploy-ключи, простой вариант: ключ, ссылка `github.com/<owner>/<repo>/settings/keys/new`,
  кнопка «Проверить». Клонирование по URL через сеанс.
- Журнал действий (clone, pull, push, копирование, замена, запуск задач).
- Встроенный TLS (`tls_cert`, `tls_key`), RPM-пакет, CI со сборкой под тегом `pam`.

## Позже и только если понадобится

- **Просмотр dev-сервера** (порт приложения через gitaway). Заложено в решениях: только
  на отдельном origin (поддомен или порт в nginx), см. `DECISIONS.md`.
- Stage отдельных фрагментов (`git apply --cached`).
- Device Flow GitHub с автоматическим добавлением deploy-ключа.
- Граф коммитов, TOTP как второй фактор.

## Сознательно не делаем

Плагины, LSP и автодополнение, отладчик, многопользовательский режим, редактор конфликтов
слияния, API GitLab и Bitbucket, собственная база пользователей, встроенный VPN.
Для доступа издалека документируем SSH-туннель, nginx с TLS и WireGuard или Tailscale.
