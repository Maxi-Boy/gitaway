# Решения для версии 0.1 (черновик)

Статус: черновик, правится по итогам прототипов.

## Цели (ориентиры, уточнить замером code-server на том же сервере)

- Один бинарник с вшитым фронтендом (`go:embed`), без Node.js на сервере.
- Потребление RAM в простое и размер пакета заметно меньше, чем у code-server
  (конкретные числа зафиксировать после замера).
- Быстрая первая загрузка интерфейса по локальной сети.
- Работа от имени обычного пользователя, как в терминале.

## Не делаем в v0.1

- Расширения и плагины, подсказки кода уровня LSP.
- Несколько пользователей и роли.
- Редактор конфликтов слияния (конфликтный файл открывается как обычный).
- Поддержка GitLab и других хостингов (сначала только GitHub).

## Конфигурация

Один файл (формат выбрать: TOML или YAML) со значениями по умолчанию, безопасными для запуска:

- `listen`: по умолчанию `127.0.0.1:<порт>`
- `roots`: разрешённые корни для репозиториев и локальной ФС
- `default_folder`: папка по умолчанию для серверной панели
- `keys_dir`: каталог ключей (права 0700)
- `pam_service`: имя PAM-сервиса
- `session_ttl`: время жизни сессии

## Длительные операции

clone, fetch, pull, push выполняются как задачи: идентификатор задачи, потоковый вывод
(WebSocket или SSE), таймаут, возможность отмены, блокировка на репозиторий
(две команды git в одном репозитории не запускаются параллельно).

## API (черновик)

| Метод и путь | Назначение |
|---|---|
| POST /api/login, POST /api/logout | вход и выход (PAM, сессионная cookie) |
| GET /api/repos, POST /api/repos | список и добавление репозиториев |
| GET/POST/DELETE /api/repos/{id}/worktrees | вкладки-ветки (git worktree) |
| GET /api/ws/{wid}/tree?path= | элементы каталога, дата на диске, статус |
| GET /api/ws/{wid}/commits?path= | последний коммит по элементам (асинхронно) |
| GET /api/ws/{wid}/status | ahead/behind, изменённые файлы |
| POST /api/ws/{wid}/fetch, /pull, /push | отдельные операции git |
| GET/PUT /api/ws/{wid}/file?path= | чтение и сохранение файла |
| POST /api/copy/plan | план копирования: файлы, конфликты (размер, даты, время коммита), пропущенное |
| POST /api/copy | выполнение копирования или перемещения с решениями по конфликтам |
| GET /api/ws/{wid}/term (WebSocket) | терминал |
| GET /api/fs?dir=&path= | содержимое папки на сервере (без dir: папка по умолчанию, иначе первый корень) |
| POST /api/fs/mkdir | новая папка {dir, path, name} |
| GET/PUT /api/settings | настройки серверной панели; PUT меняет только переданные поля |
| POST /api/git/stage, /unstage | {repo, wt, paths}: индекс; "." это вся рабочая папка |
| POST /api/git/discard | {repo, wt, paths}: вернуть к HEAD, новые файлы удалить (подтверждает интерфейс) |
| POST /api/git/commit | {repo, wt, message}: коммит из индекса, ответ с хешем |
| GET /api/diff?repo=&wt=&path=&staged=1 | diff файла (рабочая папка или индекс), до 1 МБ |
| GET /api/jobs/{id} | состояние и вывод задачи |
| GET /healthz | проверка работоспособности |

Единый формат ошибок: `{"error": {"code": "...", "message": "..."}}`.

## Безопасность (основное)

- Все пути проверяются: абсолютный вид, раскрытие symlink, префикс из `roots`.
- Аргументы git передаются списком, имена веток проверяются (не начинаются с `-`).
- WebSocket: проверка Origin и сессии. Cookie: Secure, HttpOnly, SameSite.
- Ограничение попыток входа. Пароль не логируется.
- Доступ к GitHub: deploy-ключи на репозиторий; Device Flow только для мастера
  подключения, токен не сохраняется.
- Файлы ключей и конфигурации: права 0600, каталоги 0700.

## Открытые вопросы

- (решено) Название: gitaway, лицензия: MIT.
- Минимальная версия Go и способ сборки RPM.
- Формат конфигурации.

## Статус реализации (скелет)

Сделано и покрыто тестами:

- `internal/config`: загрузка настроек (пока JSON), раскрытие `~`, проверка значений.
- `internal/fsx`: защита путей (корни, symlink, `..`).
- `internal/gitx`: запуск git, проверка входных данных, ветки, статус, ahead/behind,
  fetch/pull/push по отдельности, обновление неактивной ветки, worktree,
  последний коммит по элементам каталога (с кэшем).
- `internal/auth`: интерфейс проверки, режим токена, сессии, ограничение попыток входа.
- `internal/store`: реестр репозиториев (repos.json, права 0600).
- `internal/jobs`: блокировка операций по репозиторию.
- `internal/copyop`: копирование и перемещение между панелями: план (конфликты, данные для диалога),
  решения по файлам и массовые политики (replace_all, replace_newer, skip_all, keep_both_all),
  атомарная запись с сохранением времени изменения, защита путей, запрет копирования в себя и в .git.
- `internal/server`: API (вход, репозитории, ветки, статус, worktree, дерево файлов,
  коммиты, чтение и сохранение файла, операции git), CSRF, проверка Origin, заголовки безопасности.
- `web`: временная страница для проверки API.

Ждёт результатов прототипов (каталог `proto/`):

- PAM (`auth/pam.go` с тегом сборки `pam`): после проверки pamauth на RED OS.
- Терминал (pty + WebSocket): после проверки term.
- Подход к «последнему коммиту» уже реализован в `gitx`, но может быть доработан по замерам lastcommit.

Не сделано: клонирование по URL, deploy-ключи и мастер подключения GitHub, stage и commit,
интерфейс двухпанельного режима и диалога конфликтов (бэкенд готов), настоящий интерфейс по макету,
очередь задач с потоковым выводом.

## Копирование между панелями (copyop)

- Источник и назначение описываются как `{repo, wt, path}` (рабочая папка git) или `{dir, path}`
  (обычная папка на сервере); `items` это имена выбранных элементов относительно каталога источника.
- `plan` ничего не меняет. `copy` строит план заново и без решений по всем конфликтам отвечает 409
  `unresolved_conflicts` (со списком путей), не меняя диск.
- Решения: по файлу (`decisions`: replace, skip, keep_both) или массово (`policy`). Явное решение главнее политики.
- `replace_newer` сравнивает время изменения с точностью до секунды. Время изменения при копировании сохраняется.
- Не копируются: символические ссылки, каталоги `.git`, специальные файлы. Конфликты типов
  (файл против каталога) и совпадающие целевые имена пропускаются без потери данных.
- Файл не заменяется самим собой: при совпадении источника и цели замена пропускается, перемещение ничего не удаляет.
- Дата создания берётся через `statx` (Linux amd64 и arm64); если файловая система её не хранит, поле пустое.
- Перемещение это копирование и затем удаление источника; пустые каталоги источника удаляются.
  Для рабочей папки git это изменение, которое увидит `git status`.

## Изменения: stage, commit, diff, отмена

- Пути из запроса идут после `--` с `GIT_LITERAL_PATHSPECS=1`: `*.go` и `:(top)` это имена,
  а не шаблоны. Проверка формата в `gitx.CleanPaths`, границы через Sandbox (symlink наружу 403).
- Отмена действует по списку `git status --no-renames` для выбранных путей, а не по вводу:
  отслеживаемые файлы возвращаются к HEAD (индекс и диск), новые удаляются, игнорируемые
  не трогаются. Ответ содержит список затронутых файлов.
- Коммит только из индекса (без `-a` и без amend), текст одним аргументом `--message=`.
  Хуки репозитория выполняются. Пустой индекс это 400, а не ошибка git.
- Ответы stage, unstage, discard и commit сразу содержат свежий `status`.

## Доступ по сети и версия файла

- `allow_cidrs` в конфигурации: сети и отдельные адреса. Проверка идёт первой, до входа
  и статики; чужой адрес получает 403. Loopback разрешён всегда. Пустой список: без ограничения
  (при `listen` не на loopback в лог пишется предупреждение).
- `X-Real-IP` учитывается только при `trust_proxy` и только от loopback (nginx на той же
  машине). Это же правило действует для лимита попыток входа.
- `GET /api/file` отдаёт `version` (наносекунды mtime и размер, строкой). `PUT` с `version`
  возвращает 409, если файл изменился; без `version` записывает без проверки.
